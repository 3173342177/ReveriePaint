# 液化环形伪影修复与验证

日期：2026-09-28

## 影响范围

- C++ 液化几何、局部预览缓存、分块物化、手势结束与取消
- GLES 位移场、呈现与回读着色器、场源准备和手势代际
- Kotlin 亚像素补点、批量 JNI 缓冲所有权、录制回放、压力时间平滑
- 图层、选区、Alpha 锁仍使用既有 KisPainter 写回与 KisTransaction 事务
- 不更改普通笔刷、UI 文案、双缓冲 Bitmap 或手势 key

## 可复现根因

旧 CPU 路径将 Krita 前向映射 `F(x)` 的位移直接当成反向采样位移
`x - (F(x) - x)`，它并非 `inverse(F)(x)`
连续拖动时，即使前向映射本身未折叠，这个近似反向映射也可能出现负 Jacobian
回归台架保留了旧算法的确定性重现，要求旧实现确实出现负值，防止测试没有覆盖问题

旧 GPU 路径将整段向量乘以点到线段的遮罩后直接相加
遮罩取决于空间位置，因此它不等价于逐 dab 的映射复合
半浮点位移及默认低精度 sampler 还会吞掉累计大位移上的细小变化

另有四个独立的数据正确性问题：

1. 物化后清零局部网格，却继续从未更新的源快照读取，破坏分块边界和重复物化的一致性
2. 批量 JNI 将小数坐标截成整数，慢速小笔刷丢失真实运动
3. UI 复用的 dab 数组直接被异步 Handler 捕获，下一帧会改写引擎尚未读取的数据
4. 场源函数异步写入局部 `ok` 却立即返回该值，导致实际走 CPU 回退时 GPU 场仍被启用

## 实现

`LiquifyInverseField.h` 是无 Qt 依赖的生产逆向位移场，测试直接编译这个头文件
CPU 使用稀疏 32×32 网格块，位移和手势开始时的 Krita 共享瓦片源快照跨预览窗口保留
物化只读取位移场，绝不在行带边界清零；固定 128×32 写回块合并重复任务
每批 JNI 只消费一次物化预算，避免将预算乘以补点数量

对目标点 `p`，先计算中点 dab 的逆向增量 `v(p)`，然后从旧场的 `p-v(p)` 取样
使用 C1 连续的紧支撑遮罩，按文档距离限制 dab 步长
推拉速度采用有界响应 `s/(1+s)`，抑制源坐标被笔尖长期困住
多圈路径还需要按移动距离进行隐式弹性松弛：

```
q = p - v(p)
r = 1 / (1 + 2 * |v(p)| / radius)
Dnew(p) = v(p) + r * Dold(q)
```

松弛只作用于当前手势的位移场，按路径距离而非帧数累积
静止不产生变化；前一手势已写入源图像的形变不会被撤回
这是防止长期重复拖动产生不可分辨应变的算法取舍，并非严格无耗散的流体输运
早期仅做映射复合的方案在高压六圈测试中仍出现折叠，已舍弃

GPU 从旧场读入局部 scratch FBO，完成后仅复制 dab 矩形回场纹理
没有同纹理读写反馈，也不进行整张位移场复制
RGBA16F 的 RG 保存位移高位、BA 保存残差；高精度 sampler 配合手工双线性插值
CPU/GPU 均使用像素中心坐标和同一数学公式

场源异步准备现在返回排队是否受理，并在引擎线程显式发布源数据
源尚未就绪时保留 dab 和源暂存，回退网格时明确关闭场模式
GPU 回读、dab 消费按手势和源世代检查，丢点时拒绝不完整回读并重放完整笔迹
异步 CPU 批次使用可复用的独占缓冲；抬笔重放使用手势快照

开发期在 WSL Debian 用真实离屏 EGL/GLES 上下文执行验证，从生产 Kotlin 文件提取着色器进行编译和执行

- 8/16/30/60px 笔刷 × 0.05/0.55/1/2 强度 × 30/60/120/240 路径采样
- 小笔刷最高强度连续六圈拖动的 Jacobian 检查
- 画布边缘、稀疏块边界、空场、无效输入与手势重置

- 实际呈现/回读 shader 的 0.5/1/2/4 倍缩放和平移，画布外透明性
