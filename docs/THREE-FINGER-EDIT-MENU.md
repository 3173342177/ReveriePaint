# 三指下滑编辑菜单

日期：2026-09-29

## 范围与实现

基于 `main` 的 `f3e6d75`（v1.3.6），分支 `feat/three-finger-edit-menu`

- 设置 → 手势新增三指下滑开关，默认开启，写入已有 `paint_prefs`
- 三个固定 pointer ID 在 650ms 内共同下滑至少 48dp，才识别为菜单手势；允许少量横向偏移，并检查三个手指位移的一致性
- 全部手指抬起后显示菜单；候选期间消费触摸直到最后抬手，避免下滑后重做、画布位移和尾指落笔
- 轻点保留三指重做；未移动时仍在 420ms 后连续重做，每 110ms 一次；移动超过 8dp 后停止等待中的连续重做
- 已开始的双指导航不被抢占；滤镜预览、活动液化、变换、裁切和透光台对位沿用原有手势
- 第四根手指、手写笔混入、取消事件使本次候选失效；关闭开关恢复原多指导航路径

## 编辑语义

已有 `copyOrCutSelection` 是复制/剪切到变换或新图层，没有通用像素剪贴板，因此没有将其重命名为粘贴

新增剪贴板完全由 C++ 持有，Kotlin 只镜像可用操作标志，不在 UI 层持有像素副本

- 只复制当前普通像素图层，存在选区时按选区遮罩复制，否则复制画布范围内的像素
- 剪切使用原生撤销事务；拒绝背景、锁定、Alpha 锁定及父组锁定的图层
- 空内容复制失败时保留原剪贴板
- 粘贴保留原始画布位置，创建根级普通像素图层，可重复粘贴，可撤销；不重复套用选区遮罩
- 剪贴板只在当前画作会话内有效，新建、打开、关闭画作时释放；不接入系统剪贴板，不支持跨画作粘贴
- 新增零载荷录制操作 43/44/45，当前回放器重放复制、剪切、粘贴；旧版本回放器会跳过这些操作，不能完整还原包含这些操作的录像，但不会因新增载荷错位

## 影响范围与检查

手势：双指撤销、三指重做/连续重做、视口导航、笔模式、触控取消与离页清理

文档：当前图层、选区羽化、锁定保护、剪切/粘贴撤销、图层与缩略图刷新、录制回放、文档释放

不修改既有 JNI 签名，新增 `canvasClipboardCapabilities`、`copyCanvasToClipboard`、`pasteCanvasClipboard`，全部走 `runCore` 串行线程

**原生库已重编并同步，真机验收尚未完成，当前不应视为已验收的发布版本。**

原生验证使用 Linux 容器、NDK r25c、Qt 6.6.3（含 Core5Compat）、Krita 源码和 KF6 6.6.0 头文件环境，直接调用 CMake/Ninja 构建 arm64-v8a 引擎。实际编译发现剪切操作的 `const auto srcDev` 不允许修改 Krita 像素设备，已改为可写的 `KisPaintDeviceSP`。

环境参照 XuanTree 的 `dev/native-tools` 脚本搭建，没有合入该分支。补装 Qt 的 `qt5compat` 模块；生成的 `KoConfig.h` 需要禁用 `HAVE_OPENEXR`，以匹配仓库预编译库没有 OpenEXR half 类型符号的配置。否则会在链接阶段出现 Imath half 未定义符号。依赖头文件来自脚本下载和生成，导出/依赖检查不等同于完整运行时 ABI 或行为验证。

重编产物已 strip 并同步到 `third_party/android-native-libs/libreverie_jni.so` 和打包目录。原有导出符号全部保留，新增三个 JNI 接口均存在；56 项运行时依赖与旧库一致。旧库缺少接口时的禁用提示仍保留，避免混用二进制导致点击崩溃。

## 手势漏检修复

先检查全部三根手指的横移和上滑越界，再判断各指是否达到下滑距离，避免较早遍历的手指尚未下滑时跳过后续手指校验。新增任意指越界后回正仍被拒绝、正常分批下滑两项测试。Kotlin 编译与 320 项 JVM 测试通过，其中手势模型 11 项。
